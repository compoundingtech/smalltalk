# Deferred namespace preparation

This is an explicit Installer source mode, not a Store migration or a native admission certificate. No default Store installs its schema, queues or worker. Existing synchronous Installer operators stay available; a deferred source refuses `record`, `scan` and `catch_up` so no fallback executes an operator under the source writer.

The source owner registers a fresh source lifetime, enables deferred capture before starting any job, and retains immutable old/new input versions. `capture_deferred` runs in the admitting transaction and only appends a bounded reference to the existing journal, advances the source revision and updates bounded counters. It never calls an operator or extracts a source body. Invalid or exhausted references fence derived state while allowing valid raw admission; database failures propagate and require source-transaction rollback. Do not catch a storage error and commit the source. References are at most 4 KiB, with at most 128 JSON nodes checked before serialization; the queue has explicit row/byte limits. Durable referenced data and garbage collection remain the source owner's responsibility.

In one brief `Store::read_snapshot`, obtain `prepare_scan`, `prepare_catch_up` or `prepare_live`, capture ordinary namespace table metadata, and use `observe_row` for complete indexed point dependencies. It returns owned values, including absence. Copy the bounded native source versions referenced by the page in that same snapshot. Release the snapshot before expensive decoding/reduction. The owned `PreparedPage` retains no connection, transaction or snapshot. The source owner must declare all staged inputs, dirty cursors, rank, authority, local observations and deadline dependencies; neither a revision nor a graph MAX index proves that closure.

After release, compute pure output and add declarative full-PK `upsert`/`delete` mutations. Namespace is injected and cannot be supplied by the operator. `require_row` declares indexed post-write completeness evidence; fresh publication requires this evidence, complete scan and consumption of the exact journal prefix. It is the same source-owner attestation obligation as `validate_publication`, not a general authority check. Mark visible changes explicitly, including membership, order, fields and authorization.

`publish_prepared` runs in a short managed reactor transaction. It checks source fingerprint/epoch, schema cookie, exact namespace/job cursor or root generation/status/applied revision, all observed rows/absences, then applies only precompiled bounded SQL/parameters and checks post-write evidence. It calls no extraction, reducer or Operator callback. Conflicts roll back output and progress together and require a new snapshot/preparation. Newer source writes may remain pending beyond the applied page; no root is ready beyond that applied prefix. Reference mutation or deletion ahead of a consumer fences the source. Pruning protects every active job and ready root's applied revision.

Limits cover at most 128 aggregate input rows, observed points, writes and evidence checks, 64 KiB per declared row, 1 MiB per page, 32 output tables and 128 columns. Output tables must have namespace in the full primary key; generated/virtual tables, triggers and foreign-key edges are refused. Metadata discovery itself is bounded to 256 schema tables and 128 foreign keys per table. These are work bounds, not a measured writer-time guarantee. Index maintenance, SQLite statements and COMMIT are not preempted; commit-inclusive time still needs measurement.

Installed views use `Views::publish_prepared_installed`: a fresh Published namespace and its certified graph cut are mirrored atomically; live output is mirrored only when the Installer is fully caught up. Partial progress stays SourcePending. The source revision/availability trigger advances the independent availability cursor, even with no semantic key changes. Semantic keys are complete old/new output memberships, not queue input keys. The source owner separately supplies the certified graph cut and fresh local/authority/time evidence. A raw gap does not become ready from a retained root.

`Worker::start_pages` reuses the existing bounded worker scheduling with a native owner's page callback, without requiring `ViewRuntime` or claims-only source rules. Subscribe before scheduling; one callback owns brief read, off-writer computation and bounded publication, returning More/CaughtUp/Stopped from authoritative state. It yields between pages, stops on errors and waits on commit notifications when caught up. This scheduler supplies no source coverage, registry, Installer or Publisher. Cancellation is cooperative between pages; it cannot preempt an arbitrary callback.
