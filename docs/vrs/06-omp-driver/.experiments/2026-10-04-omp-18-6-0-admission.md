# omp 18.6.0 admission checks

## Question

The launch gate admits minors `18.0`, `18.1`, `18.3`, and `18.4`. Does `18.6.0` preserve the five delivery-critical surfaces required by OMP-R05? Unmeasured `18.2` and `18.5` remain refused.

Date: 2026-10-04. Candidate binary:
`/nix/store/iiab5by2g75lz5vym1pxkq1np9pw3w6q-omp-18.6.0/bin/omp`;
`--version` printed `omp/18.6.0`. Linux x86_64, model
`openai-codex/gpt-6.1-sol`, thinking `minimal` for probes 1–4.

## Method for extension, lifecycle, idle, and approval probes

The disposable extension logged event name, timestamp, `ctx.isIdle()`, and the
approval fields `sessionId`, `toolName`, `toolCallId`, `approvalMode`, and
`approved`. It registered `session_start`, `agent_start`, `turn_start`,
`message_start`, `message_end`, `turn_end`, `agent_end`, `agent_settled`,
`session_shutdown`, `tool_execution_start`, `tool_execution_end`,
`tool_approval_requested`, and `tool_approval_resolved`. At `agent_end`, a
25 ms timer sampled idle until the first positive observation or 80 samples.

The exact candidate was launched with:

```sh
omp --no-session --no-lsp --no-skills --no-rules --no-extensions --no-title \
  --model openai-codex/gpt-6.1-sol --thinking minimal \
  -e /tmp/omp186-four/probe.ts -p --no-tools \
  'Reply with exactly PRINT_OK' </dev/null
```

The interactive invocation omitted `-p` and asked for `INTERACTIVE_OK` in a
separate named PTY. Approval used another isolated PTY and
`--tools bash --no-pty --approval-mode always-ask` with this exact prompt:

> Run exactly this harmless bash command: printf APPROVAL_OK. Request normal
> tool approval; after execution reply with exactly APPROVAL_DONE. Do not run
> any other tool or command.

The real login HOME retained existing provider authentication without copying
or deliberately modifying credentials. XDG configuration, state, cache and
runtime directories, workspace, and PTY registry were isolated below
`/tmp/omp186-four`. Smalltalk identity, hooks, catalog and socket environment
variables were unset. No shared daemon or mission was operated.

`18.0`, `18.1`, `18.3`, and `18.4`; do not admit unmeasured minors or
prereleases, and do not change the separate exact-build harness-context
